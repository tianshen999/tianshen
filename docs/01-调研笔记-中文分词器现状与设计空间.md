# 调研笔记：中文分词器现状与设计空间

> 阶段 1 前置调研 · 2026-09（目标轮次 1）
> 本文档回答一个问题：**"中文原生分词器"这个方向，今天真实的地形是什么样？我们站在哪里？**

## 一、一个重要的事实修正：国产头部模型已经走了半步

我们此前判断"所有分词器都是英文中心的"——这个判断需要修正一半：

- **国际主流模型（GPT、Claude）确实是英文原生、中文后补的**。测试显示其中文 token 消耗比英文高 **1.11~1.64 倍**（商业新闻场景差 64%），根因是 BPE 以英文语料为主训练，汉字被过度拆解为字节/单字，中文缺乏天然分隔符，被迫承受非对称编码代价。GPT-2 时代"人工智能"会被拆成 3 个 token。
- **但 Qwen、DeepSeek 从初始设计就做了"中文第一语言"建表**：把高频汉字、常用词组整体纳入词表。横向测试中，Qwen 与 DeepSeek-V3 的中文 token 消耗全面低于英文，最低 **0.65 倍**（即中文比英文便宜 35%）。其做法是放弃纯 BPE 频率驱动逻辑，转而基于中文语义边界与构词规律主动建表。

**这意味着**：我们想做的不再是"填补中文税"（这件事国产模型已经做了），而是更进一步的三个空缺（见第三节）。

## 二、行业里已知的"反面声音"（必须诚实面对）

不是所有研究者都认为"整词/整字 token 越多越好"：

1. **字形红利论**：当汉字被 UTF-8 字节拆分为多个 token 时，共享部首（如"氵""冫""火"旁）的字在嵌入空间中自动聚类，实测模型部首识别准确率达 **89%**。而整字 token 把字形信息封装成不可解析的编号，切断了"字形—语义"的统计通道。林语堂明快打字机的部首拆解逻辑，被 BPE 无意中复现——这是"设计之外的认知红利"。
2. **编码节省 vs 推理通胀**：文言文 token 更少（"学而不思则罔" 6 token vs 现代汉语 12 token），但模型输出准确率下降 12%、延迟增 2.1 倍、重试率升 47%——省下的 token 以推理成本赎回。**token 少 ≠ 理解好**。
3. **评测指标本身在演化**：NeurIPS 2025 提出 STRR 指标（[Beyond Fertility](https://neurips.cc/virtual/2025/loc/san-diego/122433)），认为"fertility"（token/词比）之外还需衡量语义保持度。

**对我们的意义**：设计目标不能是"把中文压到最少 token"，而是"**在语义与字形结构不损失的前提下，让中文成为词表体系的一等公民**"。

## 三、真正的空缺（我们的位置）

国产模型走了半步，但有三件事没人做：

1. **纯中文原生词表**：Qwen/DeepSeek 是"中英双语优先"，词表仍为英文和其他语言保留大量席位。**完全以中文为第一公民、彻底重排优先级的词表**，无人公开做过系统实验。
2. **字形部首通道的显式设计**：部首红利目前是"意外涌现"的。**主动把部首/部件信息设计进分词器**（而不是靠字节拆分的巧合），是一个空白设计点。
3. **开源、可复现的完整对比实验**：中文原生词表 vs 现有主流词表，在 token 效率、压缩率、字形保持、下游语义四个维度上的量化对比，目前只有零散媒体测试，没有严谨的学术级开源评测。

**我们第一阶段的产出**：一个开源的纯中文原生分词器 + 上述四维度的公开评测报告。
