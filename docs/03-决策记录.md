## ADR-001：走中文原生全栈路线，不走英文体系打补丁

- **背景**：现有大模型（含国产）的英文偏见存在于分词器、预训练语料、推理训练数据三层；在其上微调只是表层适配。
- **决策**：从分词器开始自建中文原生全栈；全程开源，不考虑盈利。
- **状态**：✅ 已拍板（用户确认：2026-09）

## ADR-002：阶段 1 定位修正——不做"反击中文税"，做"纯中文第一公民 + 字形显式设计 + 开源可复现评测"

- **状态**：✅ 已拍板（基于调研，用户知情）

## ADR-003：汉字原子性（待确认）

- **背景**：国际模型将汉字拆为 UTF-8 字节是"中文税"根源；但字节拆分意外带来部首聚类红利。
- **决策草案**：汉字永不拆碎 + 用部件序列方案（B）主动保留字形通道。

## ADR-008：实现选型（第 3 轮落地）

- **训练框架**：SentencePiece Unigram（主）；HF tokenizers 预分词器方案留作后续实验。理由：SentencePiece Unigram 以 Unicode 字符为基本单位，token 永不拆碎汉字；BPE 字节合并在汉字上有随机性。
- **汉字原子性保证**：GB2312 常用字（G0/G1 源，约 8965 字）经 Unihan kIRG_GSource 字段程序化提取，作为 user_defined_symbols 强制整字入表；罕见字靠 character_coverage=0.9995 覆盖，超出者记入评测报告。
- **字形数据源**：Unihan.zip（kRSUnicode 部首/笔画、kDefinition 释义）+ CHISE IDS（部件分解），均为开源数据，本地缓存于 data/。
- **组 C 实现**：纯整字词表直接由语料字符集合生成，不走 SentencePiece，CharTokenizer 实现统一接口。
- **状态**：🟡 实现层建议（随设计决策联动调整）

## ADR-010：第 5 轮——M1 规模化语料与 32k 词表

- **语料升级**：中文维基百科 20231101 版（wikimedia/wikipedia，hf-mirror 镜像下载 parquet 分片 0/1/2，共 978MB）抽取正文，清洗去重后 **4.32 亿字符、600 万行**；与公版经典合并为 `train_all.txt`（1.2GB）。
- **组 C 大语料版**：整字词表 22,910（维基语料字符多样性远高于经典）。
- **训练提速经验**：32k 词表 × 400 万句在本机（低配 CPU）约需 1~1.5 小时；新增 `--sentence-limit` 参数（默认 500 万句 ≈ 2 亿字符），词表统计足够收敛且可大幅提速。
- **状态**：✅ 完成——32k 词表训练成功并完成对比评测（见 ADR-011 与 eval_results.md）

## ADR-011：user_defined_symbols 陷阱与原子性方案修正（第 5 轮）

- **事故**：用 user_defined_symbols 强制 GB2312 常用字（8965 字）入表后，32k 词表只学到 180 个多字词——SentencePiece 规定**包含 user-defined symbol 的片段不会被学习**，强制常用字等于封死了所有含这些字的多字词。
- **修正**：放弃强制注入；改用 `character_coverage=1.0`——语料中出现的每一个字符都作为整字 piece 入表。Unigram 模式本身以 Unicode 字符为基本单位（token 永不拆碎汉字），原子性由结构保证，无需强制。
- **权衡**：coverage=1.0 会让维基语料全部 22.9k 字符占掉词表槽位，32k 词表留给词语的余量约 9k；64k 档可留 41k 给词语（设计文档决策点 2 的双档实验因此更有必要）。
- **未覆盖字符**：语料之外的生僻字在推理时归入 <unk>。后续实验方向：在语料中追加一行全量汉字（27k 字）使词表全覆盖，代价是槽位占用（记为后续实验项）。
- **状态**：✅ 已修正并重训成功——32k 词表词构成：单字 16,296 + **多字词 9,495**（修复前仅 111）+ 其他 6,209。评测：token/字 1.2265→**1.109**，整字保持率保持 1.0，bits/字 16.60 仍全场最低。
- **遗留差距**：token/字 仍落后 DeepSeek(1.00)/Qwen(1.04)——对方词表 12.9 万/15 万，我们的 32k。64k 档实验 + 更大语料是下一轮追平的路径。
- **次生 bug 记录**：① train_unigram 内部旧默认覆盖（None→gb2312_chars）未删干净，导致重训一次仍带强制——已加防回归测试（tests/test_tokenizer.py::test_train_defaults_no_forced_symbols）；② 组 C 词表解析遇语料中的制表符字符崩溃——split 改为 maxsplit=1。

## ADR-012：第 6 轮——64k 词表、覆盖率分析与评测样本扩充

- **评测样本扩充**：新增 4 类（新闻/百科/歌词/网络用语），共 10 类。10 类平均下：bits/字 15.32 与 DeepSeek 15.30 并列第一；token/字 1.0236（vs DeepSeek 0.9015 / Qwen 0.9504）；整字保持率 1.0 保持唯一。
- **覆盖率分析工具**（src/tokenizer/coverage.py，两个踩坑）：
  - SentencePiece 未登录字 out_type=str 会返回原字形而非 <unk>，必须用 id 判断（曾误报 100% 覆盖）；
  - 单个字编码会拆成 `▁` + 字 两个 token（dummy prefix 独立成片），覆盖率/评测逻辑需剥前缀处理。
- **诚实覆盖率**：group_a_32k 对 GB2312 常用字 98.98%（缺 91 个极冷僻字），对全量 10.3 万 Unihan 汉字 16.5%（扩展 B/C/D 区未覆盖）。全字覆盖实验方向（语料追加全量汉字行 / required_chars 注入）已列入后续。
- **部首可恢复率**：全部 6 类样本 1.0——字形通道在词表层面成立（部首信息可完整恢复）。
- **状态**：✅ 64k 词表完成——词表构成：单字 15,739 + **多字词 39,594**（32k 的 4 倍）+ 其他 8,667。10 类样本评测：
  - token/字 **0.9383**：反超 Qwen2.5(0.9504)/ChatGLM(0.9644)/Yi(1.0107)/GPT-4o(1.0941)，仅落后 DeepSeek-V3(0.9015，129k 词表)；
  - bits/字 **14.98**：全场第一（DeepSeek 15.30）；
  - 整字保持率 **1.0**：全场唯一满分。
  - 结论：64k 词表已证明"纯中文原生 + 汉字原子性"与巨头词表同等甚至更优；追平 DeepSeek 只需 96k/128k 档（其词表 12.9 万）。掉线事故：会话中断导致首次 64k 训练进程终止（约 1 小时进度损失），重启后完成。

## ADR-013：英文通道从"混训组 B"改为"分离式挂件架构"（用户拍板）

- **用户决策**：终极目标是全中文体系（软件栈直至硬件）；现阶段允许为跑通设备预留通道，但**不得作为核心部件**，必须是随时可切断、不影响全中文体系的挂件板块。
- **事实澄清（写入设计认知）**：硬件处理位流、语言中立；"英文"存在于软件栈（固件/OS/编译器/协议），全中文化是软件栈工程，不需要重造硬件。
- **评估结论**：核心词表必须含**数字与标点**（中文文本固有组成，非英文）；**拉丁字母**处理做成挂件。
- **架构决策**：放弃组 B 混训（英文混入词表后无法切除），改为**分离式双词表**：
  - 核心：纯中文 + 数字 + 标点（现有 64k 主线继续）；
  - 挂件：拉丁子词词表，独立训练、独立文件、默认关闭、一行配置启用；
  - 切断保证：禁用后核心行为逐字节不变，用测试证明"切断无副作用"；
  - 评测：挂件代价/收益量化表（混排文本省 token vs 纯中文损失）。
- **状态**：✅ 已实现——CompositeTokenizer（纯 ASCII 片段才路由到挂件，其余永远走核心）、plug_en 8k 词表（公版英文经典训练）、默认关闭开关、19 测试全绿（含切断无副作用 + id 空间偏移测试）。
- **实测发现（诚实记录）**：纯中文 8 类样本挂件开/关**零差异**（核心完全隔离）；但混排样本开挂件反而 -1~-2 token——核心词表（维基语料自带 ASCII）已学会 "Transformer" 等现代词汇的拉丁子词，小挂件（19 世纪小说语料）反而不如。结论：**架构与开关已验证；挂件词表质量需现代英文语料再训练**（v1.1 待办），当前默认关闭即为最优。

## ADR-009：第 4 轮——环境打通与首次端到端实验

- **便携 Python**：工作区内 tools/python/（python.org embeddable 3.12.10 + get-pip），零系统改动；`tools/py.cmd` 因 cmd 代码页问题废弃，统一用 PowerShell 内联环境变量。
- **沙箱兼容补丁（重要）**：tools/python/sitecustomize.py 修补 tempfile.mkdtemp——Windows 下 CPython 以 0o700 建目录、生成仅所有者 DACL，沙箱安全上下文无法写入（WinError 5/13）；改用 os.makedirs 继承父目录 ACL。同时把工作目录注入 sys.path。
- **SentencePiece 三连坑**：① 预编译字符映射表在含中文路径下加载失败 → 改 identity 归一化（顺带更符合"保真"原则，写入设计原则）；② user_defined_symbols 必须逐元素列表，逗号拼接会被当成一个超长 piece；③ C++ 窄字符 API 打不开含中文的绝对路径 → 一律用工作区内 ASCII 相对路径。
- **网络路径**：Schannel/PowerShell TLS 被沙箱限制 → 用 Node(OpenSSL) 下载；pip 走清华镜像；HuggingFace 走 hf-mirror.com 镜像。
- **首份训练语料**：Project Gutenberg 公版经典 5 部（三国演义/西游记/红楼梦等，~8MB，中文占比 92%+），清洗后 7.5 万行。
- **首次实验结果（smoke）**：group_a 词表 9704（9302 单字 + 116 多字词）；整字保持率 1.0（vs GPT-3.5 0.68、GPT-4o 0.87、Qwen 0.93、DeepSeek 0.91）；bits/字 16.24 全场最低；token/字 1.23 暂落后 DeepSeek 1.00/Qwen 1.04——原因是小词表只有 116 个多字词，扩大词表与语料后可预期追平（见下一轮 M1）。
- **状态**：✅ 已验证（12 测试全绿 + 报告生成）
