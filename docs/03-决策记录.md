## ADR-021：词表底层架构升级——真三维词空间（用户拍板）

- **用户决策**：不做"二维存储+三维视图"的妥协方案；词表底层直接采用**全三维架构**，因为基底维度决定未来通用机器人大脑是"真三维还是假三维"。
- **架构定义**：每个词 = 三维语义空间中的一个点，坐标由三个**正交语义平面**的直和构成：
  - 形平面 F：部首 one-hot ⊕ 部件 one-hot ⊕ 结构类型 ⊕ 笔画（可由现有 Unihan/IDS 数据直接计算）；
  - 音平面 P：声母 ⊕ 韵母 ⊕ 声调（可由现有拼音数据直接计算）；
  - 意平面 S：义素/语义特征向量（意阶段的核心产出）。
  - WordVector = F ⊕ P ⊕ S（稀疏高维；各平面可独立启用/切断——挂件原则延伸到向量层）。
- **真三维的判定标准**：维度存在于**表示与几何**（向量空间中的距离/相似性），不存在于文件格式。同部首字在形子空间聚类、押韵词在音子空间聚类、同义词在意子空间聚类——可计算的真实几何。
- **与未来大脑的关系**：该词空间作为机器人语义底座的**锚点集与坐标种子**；后续小规模预训练时作为嵌入初始化/辅助特征（承接"部首红利"研究结论）。
- **状态**：✅ 已拍板；形/音平面在 v0.3 意阶段与意平面一起组装成完整三维空间。

## ADR-022：v0.3a 首轮维度证书——满秩但谱集中，加权方案升级（第 1 轮）

- **首轮证书结果**（artifacts/semantic/certificates.json/.md）：
  - 形平面 F：标称 870 维，实测秩 **868/870**——维度无缺失（真三维的第一道关通过）；
  - 音平面 P：标称 73 维，实测秩 69；拼装 W：秩 937/943——同样无缺失；
  - 但参与率 PR=22.8（F）/19.7（P），远低于满秩理论值 → 判定 **CONCENTRATED 谱集中**：高频部首（氵木扌口…）主导能量分布——这是汉字频率的真实结构，不是假三维；
  - **独立性检验通过**：F⊥P 最大典型相关 ρ_max=0.0001，R²=2.2%——两平面近似正交；
  - twoNN 本征维度 ≈1.7~2.4（去重后）→ 局部几何呈低维流形（one-hot 词袋的固有性质，记录在案）。
- **修订 2 决定**：行内平方根加权无效（PR 22.77→22.26，因集中来自"特征跨字频率"而非"字内计数"）——改用**列向 IDF 加权**（log(N/df)，抑制高频部件/读音维度）重新构建并复检。
- **形声字检测教训**：全音节精确匹配只圈出 56.4% 且其 F→P 相关（R² 3.2%）未高于非形声组（4.0%）——原因是精确匹配标准过严（声旁常只押韵或只同声），且全局回归稀释了单维信号。改为**部件→读音的互信息定向检验**（每个部件对其承载字的声母/韵母分布 vs 基线）。
- **状态**：✅ v0.3a 完成。最终证书（artifacts/semantic/certificates.json）：
  - 秩检验全部通过（F 868/870、P 69/73、W 937/943）——无维度缺失，真三维第一道关成立；
  - IDF 加权生效（F：PR 22.8→95.5，各向异性 0.35→0.17）；置换零模型 z：F·IDF=-341（部首层级凝聚——真实结构）、P·IDF=+4.6（散布型）、W=+37；
  - F⊥P 正交（ρ_max=0.0001）；
  - 定向形声检验成立：部件→读音 MI>0，弗→f 提升 34.6x、𢎥→r 34.9x 等——中文"形声"结构获得量化证据；
  - 45 测试全绿。**评估结论：证书通过，可进入意平面。**

## ADR-027：简繁分离——简体为主、繁体挂件（用户拍板）

- **用户决策**：简体为主，繁体做挂件——简体与繁体混在一起会在后续增加不必要工作流。
- **现状核实（数据）**：字符平面 16,198 字中繁体 4,147（25.6%）；多字词 55.6% 含繁体字；根源是形阶段"维基（简）+ 公版经典（繁）"混训语料，繁体渗入词表→拼音→意平面全链路。
- **架构方案**（沿用 ADR-013 挂件模式）：
  - **核心**：简体 + 通用（无简繁区分）字符为锚点，承载 F/P/S 三平面坐标；
  - **繁体挂件**：繁→简 映射索引（繁字不占独立坐标，路由到对应简字的向量）+ 繁体专属读音/义项数据（traditional_map.json 已独立），默认关闭、可切断；
  - 词级：含繁字的词先转简再聚合；
  - 脚本判定数据源：Unihan kSimplifiedVariant/kTraditionalVariant + CEDICT 简繁对。
- **执行时机**：v0.3 发布前修复（发布后返工 = 真正的不必要工作流）。
- **修复结果**：核心字符集 12,051（剔除繁体 4,147）；核心词集 31,473（转简去重 -8,011）；繁体挂件索引 trad_index.json（繁→简路由）；全平面按核心重建并复检——深义层独立性 R²=0.0201 仍通过；义近评测 S2 Hit@10 0.194→**0.222**（去繁噪声后提升）；54 测试全绿；发布包更新（117 文件 / 23.16MB）。
- **状态**：✅ 修复完成，v0.3 发布物就绪（仍待令牌推送）

## ADR-028：全系统深度审计（用户要求）——抓到并修复严重隐性 bug

## ADR-029：大版本发布闸门——自动审计 + 自动校准（用户拍板）

- **用户决策**：整个系统每次大版本更新，都必须执行一次自动审计与自动校准。
- **机制**：tools/audit_gate.ps1 为唯一发布闸门，依次执行：
  1. 单元测试（pytest 全量）；
  2. 数据一致性复核（review_v02：拼音/繁体/ADR 结构）；
  3. 全系统深度审计（audit_full：平面键一致、核心纯净、挂件路由、零向量、覆盖、证书一致）；
  4. 自动校准：重跑 certify_planes / certify_meaning（维度证书重新生成 = 校准）；
  5. 评测基线复跑：polyphone_bench / semantic_bench / token_economy；
  6. 阈值判定（gate_check.py）：独立性 R² < 0.3、义近 S2 Hit@10 ≥ 0.19、多音 100%、秩判据全部通过。
- **规则**：任一环节失败或阈值不达标 → 闸门不通过，禁止发布；报告 artifacts/audit_gate_report.md 归档。

## ADR-030：闸门校准标准升级——简繁特征校准 + 共线去重 + 结构依赖预算（用户评估授权）

- **用户发现**："液體"的"體"是繁体——维基词典释义为繁体文本，深义层关键词特征被繁体污染（简体核心原则在特征层被破坏）。用户授权评估：共线去重与结构依赖预算何时加/何时去。
- **评估结论（三项全部现在加，永久保留）**：三者均为"校准层"，与数据规模无关；小数据时钉死，大数据时才不会积累隐患。
  1. **简繁特征校准**：释义文本先转简再分词；停用词同步转简。关键词词表 2000→1737 维，含繁体关键词 0。
  2. **共线列去重**：完全同形的关键词列（共现词对）合并为一维。
  3. **结构依赖预算**：取代 0.8×名义维 的粗糙判据——按 one-hot 特征块计算"可达最大秩"（块内求和为 1 的合法依赖计入预算），判据改为 **实测秩 ≥ 0.95 × 可达秩**。
- **效果**：深义层 实测秩 1544 / 可达 1544 = **1.0**；全平面过闸（9/9）；判据从此随数据规模自适应，不靠拍脑袋的 80%。
- **形/音平面同校（用户追问后补齐）**：① 形平面部件词表经简繁校准（繁体部件 421→0，词表 845→823 列）；② F/P 共线列逐块合并（校准层）；③ 结构预算：F 秩/可达 0.9988、P·IDF 1.0；④ 闸门顺序修正：先校准后审计（审计必须检查校准后的产物）。
- **状态**：✅ 三平面校准链齐备并过闸

## ADR-031：新板块接入协议——通用校准自动适用，领域探针人工策展（用户追问后落地）

- **用户追问**：以后接入新板块（新平面/新特征族/新挂件），自动校准机制要不要每次重新配？
- **结论**：**机制自动、判题人工**。通用校准机制（结构依赖预算、证书闸门发现、IDF/剪枝/共线合并/简繁校准）零声明自动适用；领域探针（义近 PROBES、多音判题集、独立性参照、板块专属不变量）必须每个新板块人工策展一次。
- **本次落地**（详见 docs/10-新板块接入协议.md）：
  1. `kakeya_check.certify()` 默认 `auto_blocks=True`：不传 block_sizes 时 `detect_blocks()` 自动识别 one-hot 块 → 结构依赖预算自动计算，新板块零声明接入；
  2. `gate_check.py` 自动扫描 `artifacts/semantic/*_certificates.json`：新板块证书按命名约定落盘即被闸门判定，无需改闸门代码；
  3. 拼装平面 W/W3 显式 `auto_blocks=False` 豁免（跨平面冗余属预期，不算缺陷）；
  4. 单元测试 +3（自动识别 / auto 预算 / 显式分块与豁免），证书报告新增结构预算明细行；
  5. 新增 `tools/e2e_check.py` 端到端贯通验证并入闸（一条文本走完 形→音→意 + 四挂件路由，全断言），并把词级平面重建 `tools/build_word_planes.py` 补进闸门校准链（此前只校验不重建），闸门由 9 步扩为 11 步。

## ADR-008：实现选型（第 3 轮落地）

- **训练框架**：SentencePiece Unigram（主）；HF tokenizers 预分词器方案留作后续实验。理由：SentencePiece Unigram 以 Unicode 字符为基本单位，token 永不拆碎汉字；BPE 字节合并在汉字上有随机性。
- **汉字原子性保证**：GB2312 常用字（G0/G1 源，约 8965 字）经 Unihan kIRG_GSource 字段程序化提取，作为 user_defined_symbols 强制整字入表；罕见字靠 character_coverage=0.9995 覆盖，超出者记入评测报告。
- **字形数据源**：Unihan.zip（kRSUnicode 部首/笔画、kDefinition 释义）+ CHISE IDS（部件分解），均为开源数据，本地缓存于 data/。
- **组 C 实现**：纯整字词表直接由语料字符集合生成，不走 SentencePiece，CharTokenizer 实现统一接口。
- **状态**：🟡 实现层建议（随设计决策联动调整）

## ADR-011：user_defined_symbols 陷阱与原子性方案修正（第 5 轮）

- **事故**：用 user_defined_symbols 强制 GB2312 常用字（8965 字）入表后，32k 词表只学到 180 个多字词——SentencePiece 规定**包含 user-defined symbol 的片段不会被学习**，强制常用字等于封死了所有含这些字的多字词。
- **修正**：放弃强制注入；改用 `character_coverage=1.0`——语料中出现的每一个字符都作为整字 piece 入表。Unigram 模式本身以 Unicode 字符为基本单位（token 永不拆碎汉字），原子性由结构保证，无需强制。
- **权衡**：coverage=1.0 会让维基语料全部 22.9k 字符占掉词表槽位，32k 词表留给词语的余量约 9k；64k 档可留 41k 给词语（设计文档决策点 2 的双档实验因此更有必要）。
- **未覆盖字符**：语料之外的生僻字在推理时归入 <unk>。后续实验方向：在语料中追加一行全量汉字（27k 字）使词表全覆盖，代价是槽位占用（记为后续实验项）。
- **状态**：✅ 已修正并重训成功——32k 词表词构成：单字 16,296 + **多字词 9,495**（修复前仅 111）+ 其他 6,209。评测：token/字 1.2265→**1.109**，整字保持率保持 1.0，bits/字 16.60 仍全场最低。
- **遗留差距**：token/字 仍落后 DeepSeek(1.00)/Qwen(1.04)——对方词表 12.9 万/15 万，我们的 32k。64k 档实验 + 更大语料是下一轮追平的路径。
- **次生 bug 记录**：① train_unigram 内部旧默认覆盖（None→gb2312_chars）未删干净，导致重训一次仍带强制——已加防回归测试（tests/test_tokenizer.py::test_train_defaults_no_forced_symbols）；② 组 C 词表解析遇语料中的制表符字符崩溃——split 改为 maxsplit=1。

## ADR-013：英文通道从"混训组 B"改为"分离式挂件架构"（用户拍板）

- **用户决策**：终极目标是全中文体系（软件栈直至硬件）；现阶段允许为跑通设备预留通道，但**不得作为核心部件**，必须是随时可切断、不影响全中文体系的挂件板块。
- **事实澄清（写入设计认知）**：硬件处理位流、语言中立；"英文"存在于软件栈（固件/OS/编译器/协议），全中文化是软件栈工程，不需要重造硬件。
- **评估结论**：核心词表必须含**数字与标点**（中文文本固有组成，非英文）；**拉丁字母**处理做成挂件。
- **架构决策**：放弃组 B 混训（英文混入词表后无法切除），改为**分离式双词表**：
  - 核心：纯中文 + 数字 + 标点（现有 64k 主线继续）；
  - 挂件：拉丁子词词表，独立训练、独立文件、默认关闭、一行配置启用；
  - 切断保证：禁用后核心行为逐字节不变，用测试证明"切断无副作用"；
  - 评测：挂件代价/收益量化表（混排文本省 token vs 纯中文损失）。
- **状态**：✅ 已实现——CompositeTokenizer（纯 ASCII 片段才路由到挂件，其余永远走核心）、plug_en 8k 词表（公版英文经典训练）、默认关闭开关、19 测试全绿（含切断无副作用 + id 空间偏移测试）。
- **实测发现（诚实记录）**：纯中文 8 类样本挂件开/关**零差异**（核心完全隔离）；但混排样本开挂件反而 -1~-2 token——核心词表（维基语料自带 ASCII）已学会 "Transformer" 等现代词汇的拉丁子词，小挂件（19 世纪小说语料）反而不如。结论：**架构与开关已验证；挂件词表质量需现代英文语料再训练**（v1.1 待办），当前默认关闭即为最优。

## ADR-016：音阶段表示方案——拼音为主，注音为挂件（用户拍板）
